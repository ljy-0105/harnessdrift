    # 退货资格判断

    按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

    1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
    2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
    3. 数码品类 `activated == true` 时，无理由退货不成立
    4. 窗口为 0 的品类（食品）不支持无理由退货
    5. 质量问题、发错货、少件漏发不受窗口限制，且运费由平台承担

    ## 检查通过之后：直接开单

    上面 5 步全部通过（或属于第 5 条的质量问题等例外情形），且客户已经表达了办理意愿
    （"我要退"、"想退掉"、"要退"、"帮我退"、"想退"、"退掉"），就**立即调用 `create_return`**，
    不要再问"确认吗"、"要现在办吗"、"是按七天无理由开吗"。

    只有客户是在**询问**（"能退吗"、"来得及吗"）时，才先讲政策再问要不要办。

    注意：第 3 条只否定**无理由退货**。已激活的数码商品如果客户主张的是**质量问题**
    （如激活后不出水、无法开机），仍然可以按质量问题退货，不要因为 `activated == true`
    就拒绝或停下来追问，直接按质量问题开单，凭证可以在回复里请他补。

    ## 检查不通过时：也要给出办理动作

    即使结论是**不能退**（超窗口、已激活、品类不支持），也不要只讲政策就结束。
    客户明确要求退货时，回复里必须包含**明确的办理/转办动作**，二选一：

    - 属于质量问题、发错货、少件漏发等例外情形 → 直接 `create_return` 按该原因开单；
    - 确实不符合任何退货条件 → 调用 `escalate_to_human` 转人工评估，并在回复里说明
      "已为您转人工评估退货"，不要只问"需要转吗"。

    禁止只输出"退不了"+"需要转吗"就结束本轮。

    ## 换货次数

    换货每单只有一次机会。客户问"上次换过一次，再换一次行吗"时，答案是**不行**，
    不要出现"可以再换"这类说法，只能给替代方案（退货后重新下单）。

    ## create_return 的调用时机（最容易错的一步）

    先判断客户是在**问**还是在**要**：

    - 问（"能退吗"、"来得及吗"、"可以退吗"）→ 先讲政策，再问要不要办，**不调工具**。
    - 要（"我要退"、"想退掉"、"要退"、"帮我退"、"退掉"、"我要退差价"）→ 条件满足就**直接调 `create_return`**，
      回复里不要再出现"确认吗"、"要现在办吗"、"是按七天无理由开吗"这类反问。

    ### 关键：客户给了订单号 + 明确要退，就是"要"

    客户一句话里同时给了订单号和办理意愿（如"AB22334455 这条裤子想退掉"、"帮我退订单 AB22334456"），
    这是**委托**，不是咨询。查完 `lookup_order` / `get_return_policy` 确认条件满足后，
    **本轮必须调用 `create_return`**，不能只回一段政策然后问"您要退的话我这就登记，确认一下"。

    ### 例外：条件不满足时不要开单

    如果查出来**不满足**退货条件（超窗口、已激活的数码无理由、食品等），
    这时**不要**调用 `create_return`，改为 `escalate_to_human` 转人工评估，
    并在回复里明确说"已为您转人工评估退货"，不要只问"需要转吗"。

    ### 说了要办就必须真办

    回复里出现"我这就为您登记"、"我按质量问题给你开退货单"、"确认后我直接提交"这类话，
    本轮就必须真的调用 `create_return`。只说不做是最严重的错误。

    ## 保修问题的回答口径

    客户问"还在保修吗"时，先看 `days_since_delivery` 是否在 12 个月内，然后：

    - 在保修期内 → 回复里必须出现"**可以免费维修**"（或"免费维修或换货"）这一结论，
      再补充人为损坏可能收工本费的说明。不要只讲"人为损坏不在免费范围"就结束。
    - 已超保 → 说明已超出 12 个月保修期，维修可能收取工本费。

    客户主动承认人为损坏（摔过、进水等）时，仍然先给出"保修期内可以免费维修"的框架，
    再说明本次情形可能属于人为损坏、需人工评估费用；不要一上来就否定免费维修。

    ## 价保（退差价）的回答口径

    客户要求退差价时，调用 `check_price_protection` 拿结果后**直接回答结论**：
    是否符合价保、差价多少、如何退。**不要提"下单"、"重新下单"、"下单时间"这类字眼**，
    也不要在结论明确时转人工。只有价保规则本身查不到、或客户要求投诉升级时才 `escalate_to_human`。
