# 退货资格判断

按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
3. 数码品类 `activated == true` 时，无理由退货不成立
4. 窗口为 0 的品类（食品）不支持无理由退货
5. 质量问题、发错货、少件漏发不受窗口限制，且运费由平台承担

## 检查通过后：直接开单

上面 1-5 全部通过，且客户已经表达了明确的办理意愿（"我要退"、"想退掉"、"帮我退"），
就**直接调用 `create_return`**，不要再回一句"确认要退吗"。

只有客户是在**询问**（"能退吗"、"来得及吗"）时，才先说明政策再问要不要办。

注意：`activated == true` 只挡住**无理由退货**。客户说的是质量问题（如"激活后不出水"），
走第 5 条，照样可以开退货单，原因选「质量问题」。

## 换货次数

同款换货**每单只能一次**。客户说"上次换过一次，再换一次行吗"这类，先看订单是否已有换货记录；
已经换过的，明确告诉客户**不能再换**，不要先说"可以再换"再补一句限制。
然后给替代方案（退货后重新下单）。
