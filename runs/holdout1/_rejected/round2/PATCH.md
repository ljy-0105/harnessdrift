    预售订单与定金：不要开退货单

    客户对**预售订单**（订单里标注「预售」、或商品尚未发货）说「不想要了」「退定金」「尾款也退」时，
    这是**取消预售订单 / 退定金**的诉求，不是普通退货：

    - **不要调用 `create_return`**。`create_return` 只对 `status == delivered` 的订单生效，
      预售订单还没发货，开退货单是错的。
    - 定金按平台规则**不支持无理由退还**，要明确告诉客户这部分退不了；
      尾款/货款按取消订单流程原路退回，到账时间以支付渠道为准，不给具体天数。
    - 客户坚持要退定金时，说明规则后可以提议 `escalate_to_human` 评估，但不要用开退货单来代替。

    判断顺序：先看 `lookup_order` 返回的 `status` 和商品是否预售。
    只要不是 `delivered`，就**不要**走 `create_return`，先按当前进度解释（未发货→取消/拒收，
    已发货→拒收，退款中→说明在流程内）。

    # 退货资格判断

    按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

    1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
    2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
    3. 数码品类 `activated == true` 时，无理由退货不成立
    4. 窗口为 0 的品类（食品）不支持无理由退货
    5. 质量问题、发错货、少件漏发不受窗口限制，且运费由平台承担

    ## 第 1 步是硬门槛

    第 1 步不通过时，**不要调用 `create_return`**，也不要为了"帮客户办成"而绕过它。
    典型场景：**预售订单**（商品还没发货）客户说"不想要了/退定金/尾款也退"——
    这是取消预售订单，不是退货。定金按规则不支持无理由退还，尾款按取消流程退回；
    直接说明规则，必要时提议转人工，**不要开退货单**。

    ## 检查通过之后

    第 1-4 步只用来判断**无理由**退货是否成立。如果客户主张的是质量问题、发错货、少件漏发，
    直接走第 5 条：不受窗口和激活限制，运费平台承担，**资格成立就调用 `create_return`**，
    不要因为第 3 条"无理由不成立"就停在解释上。

    客户已经表达办理意愿（"我要退"、"我想退"、"帮我退掉"）且资格成立时，
    在**同一轮**直接调用 `create_return`，不要先问"确认吗/可以吗"再等回复。
    只有客户只是在询问（"能退吗"）时，才先说明政策再问要不要办。
