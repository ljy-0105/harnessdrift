    ## 预售订单与定金：不要开退货单

    客户对**预售订单**（订单里标注「预售」、或商品为预售商品）提出退款、退定金、退尾款时，
    这是**定金/尾款规则问题，不是无理由退货**，不要调用 `create_return`。

    - 定金：支付后**不支持无理由退还**，直接说明这一点，不要开退货单。
    - 尾款：按活动规则处理；客户已付尾款且商品已签收的，才可能涉及退货流程，
      但也要先确认客户要退的是尾款对应的商品，而不是把「退定金」当成退货理由。
    - 客户只是说「不想要了，定金退给我，尾款也退」时，属于**询问/主张退款**，
      先说明定金不退、尾款如何处理，再问客户是否要就尾款部分办理退货。
      不要在同一轮直接开退货单。

    判断顺序：先看订单是不是预售、客户诉求是不是围绕定金/尾款；
    是的话走本文件，不要走 `skills/return_eligibility` 的无理由退货流程。

    # 退货资格判断

    按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

    1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
    2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
    3. 数码品类 `activated == true` 时，无理由退货不成立
    4. 窗口为 0 的品类（食品）不支持无理由退货
    5. 质量问题、发错货、少件漏发不受窗口限制，且运费由平台承担

    ## 先排除：预售定金/尾款

    如果订单是**预售订单**，且客户的诉求是「退定金」「退尾款」「不想要了定金退给我」，
    这属于定金规则问题，**不要调用 `create_return`**，按 `tool_descriptions/preorder_deposit.md`
    处理：定金不支持无理由退还，先说明规则再问客户是否要就尾款部分办理退货。

    ## 检查通过之后

    第 1-4 步只用来判断**无理由**退货是否成立。如果客户主张的是质量问题、发错货、少件漏发，
    直接走第 5 条：不受窗口和激活限制，运费平台承担，**资格成立就调用 `create_return`**，
    不要因为第 3 条"无理由不成立"就停在解释上。

    客户已经表达办理意愿（"我要退"、"我想退"、"帮我退掉"）且资格成立时，
    在**同一轮**直接调用 `create_return`，不要先问"确认吗/可以吗"再等回复。
    只有客户只是在询问（"能退吗"）时，才先说明政策再问要不要办。

    注意：以上「直接开单」只适用于普通商品的退货。预售定金/尾款诉求先按上面的排除条款处理。
