# 退货资格判断

按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
3. 数码品类 `activated == true` 时，无理由退货不成立
4. 窗口为 0 的品类（食品）不支持无理由退货
5. 质量问题、发错货、少件漏发不受窗口限制，也不受第 3 条激活限制，且运费由平台承担

## 先判断资格，再判断要不要开单

第 1~5 步是**资格判断**，它只回答"能不能退"，不回答"现在要不要开单"。
资格通过不等于立刻开单——开单还要看客户有没有明确要求办理，以及信息是否齐全。

- **资格不通过**（超窗口、激活、品类不支持等）→ 停下，说明原因和替代方案，
  **不要调用 `create_return`**。客户说"想退"也不能开，政策是硬边界。
- **资格通过但客户只是在问**（"能退吗""来得及吗"）→ 说明政策并问要不要办。
- **资格通过且客户已表达办理意愿**（"想退""要退""帮我退""一起退"）→ 直接调用
  `create_return`，开完单再告诉客户运费和后续。
- **资格通过但关键信息缺失**（订单号没给、要退哪件商品不明确、退货原因不明）→
  先追问补齐，**不要猜、不要替客户选一个原因就开单**。

多个商品时逐个走这套流程，能退且客户已要求的当场开单，不要攒到最后一起问。
