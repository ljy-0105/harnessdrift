    # 退货资格判断

    按顺序检查，任何一步不通过就停下，把不通过的那一条讲给客户：

    1. `create_return` 只对 `status == delivered` 生效，其余状态先解释当前进度
    2. 查该品类的 `return_window_days`，用 `days_since_delivery` 比较（等于窗口当天仍然可以）
    3. 数码品类 `activated == true` 时，无理由退货不成立
    4. 窗口为 0 的品类（食品）不支持无理由退货
    5. 质量问题、发错货、少件漏发不受窗口限制，且运费由平台承担

    ## 检查通过后：直接开单

    上面 1-5 全部通过，且客户已经表达了办理意愿（"我要退"、"帮我退"、"退了吧"），
    **立刻调用 `create_return`**，不要再回一句"可以吗 / 确认吗 / 我这就给您开单，行吗"。
    把政策说明放在开单之后一起讲，或者干脆只讲关键点（运费谁承担、下一步做什么）。

    只有一种情况可以先不开单：客户只是在问（"能退吗"、"来得及吗"），
    或者缺少必需凭证（破损索赔缺照片/视频）。除此之外，条件满足就开单。

    ## 破损索赔：先要凭证，再登记

    客户说商品破损/裂了/碎了时，`file_damage_claim` 需要**开箱视频和照片两者齐全**。
    客户只提供了其中一项（例如只有视频），**不要调用 `file_damage_claim`**，
    先明确告诉客户还缺哪一项，请其补齐；补齐后再登记。
    同一轮里客户还问了别的事（如价保），可以一并回答，但破损这一项停在"要凭证"。

    ## 凭证齐全才登记，缺一项就停在索要

    判断"凭证是否齐全"只看客户**这一轮实际提供了什么**，不要替客户假设、也不要因为
    客户说"我有开箱视频"就认为照片也有了。视频和照片是两项独立凭证：

    - 只提到/只提供了视频 → 缺照片，**不调用 `file_damage_claim`**，先索要照片
    - 只提到/只提供了照片 → 缺视频，**不调用 `file_damage_claim`**，先索要视频
    - 两项都明确提供 → 才调用 `file_damage_claim`

    客户在同一轮里还问了别的事（价保、退货等），那些事照常处理，但破损这一项必须
    停在"索要缺失凭证"，不能顺手把索赔登记掉。

    ## lookup_order

    只接受完整的订单号（形如 AB12345678）。没有按客户名、手机号、商品模糊搜索的能力，
    所以客户没给单号时**只能反问**，不要在参数里塞占位符。

    返回里要看三个字段：

    - `status`：只有 `delivered` 才能发起退货；`shipped` 引导客户拒收；`refunding`/`refunded` 说明已在流程内
    - `days_since_delivery`：从签收日算起的天数，退货窗口用它判断
    - `activated`：数码品类里这一项为 `true` 表示已激活

    客户一条消息里给了多个订单号时，逐个查、逐个回答，不要漏掉任何一个。

    ## get_return_policy

    按品类查窗口天数和是否支持无理由退货。不同品类窗口不同（家居 15 天，服饰/鞋靴/数码 7 天，
    食品不支持），**不要用统一天数回答**。质量问题的退货运费由平台承担，无理由退货由客户承担 12 元。

    查完政策、条件满足、客户已要求办理的，**接着调用 `create_return`**，
    不要停在"可以退，要办吗"。

    ## create_return

    客户已明确要求退货且资格检查全部通过时调用。调用后再向客户说明运费承担方和后续步骤。
    不要为了"再确认一次"而推迟调用。

    ## file_damage_claim

    仅在客户已提供**开箱视频和照片两者**时调用。缺任何一项都先向客户索要，不要提前登记。

    判断依据是客户**这一轮消息里实际给出的凭证**，不是"客户说有"：

    - 消息里只出现"开箱视频"（哪怕说"我有开箱视频"）→ 照片缺失，**不调用**，先要照片
    - 消息里只出现"照片" → 视频缺失，**不调用**，先要视频
    - 视频和照片都明确给出 → 才调用

    客户同一轮还问了别的事（价保、退货等），那些照常处理；破损这一项停在索要缺失凭证，
    不要因为"顺手一起办"就提前调用 `file_damage_claim`。
